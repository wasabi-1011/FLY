## 1. 项目背景与目标

### 1.1 背景

FLY 是一个自有服装品牌。当前品牌在线上缺乏统一的官方阵地：社交媒体账号分散、第三方电商店铺无法承载品牌叙事、消费者难以系统了解品牌主张与当季系列，也缺少可靠的官方渠道查询线下门店。

我们参考 PEACEBIRD 太平鸟官网（www.peacebird.com）的形态——**以品牌内容为绝对核心、以视觉叙事驱动、弱化交易**的官网范式，建设 FLY 品牌官网。

### 1.2 要解决的三个真实问题

| # | 问题 | 现状痛点 | 官网解法 |
|---|---|---|---|
| P1 | **品牌没有"被完整讲述"的地方** | 品牌主张、设计语言、系列灵感散落在各处，消费者无法形成整体认知 | 首页大视觉 + 品牌故事 + 系列大片，构建完整的品牌叙事主线 |
| P2 | **当季新品触达不到潜在顾客** | 新品信息依赖电商平台详情页，缺乏编辑感与场景感，无法激发兴趣 | 系列/款式展示模块，以 Lookbook 形态呈现当季产品 |
| P3 | **门店信息不可信、不可查** | 消费者搜索到的门店信息过期、地址不准、无法判断是否就近可达 | 官方门店查询 + 全国地图，总部统一维护，权威可信 |

### 1.3 业务目标（Why）

| 目标 | 说明 | 衡量方式（上线后 6 个月） |
|---|---|---|
| G1 建立品牌数字化门面 | 成为品牌对外唯一的官方权威信息源 | 官网成为品牌词搜索的首条结果 |
| G2 提升品牌认知与好感 | 通过内容传递品牌价值主张 | 内容页人均浏览页数 ≥ [TBD]，平均停留时长 ≥ [TBD] |
| G3 为线下门店导流 | 让"看到品牌"的人能"找到门店" | 门店页访问量占比 ≥ [TBD]，门店查询使用率 ≥ [TBD] |
| G4 沉淀可运营的内容资产 | 内容更新不依赖研发发版，运营可自助 | 换季上新内容更新周期 ≤ 1 天，且无需研发介入 |

> **说明**：本官网**不承载销售转化指标**（无在线交易）。它的价值是品牌资产与到店引流，不是 GMV。请勿用电商 GMV 口径考核本项目——这是本 PRD 最重要的判断之一。

### 1.4 成功标准（Definition of Success）

一期上线后 3 个月内达成以下全部条件，判定项目成功：

- [ ] 官网在主流搜索引擎可通过「FLY + 品牌/女装/男装 [按实际品类]」检索到，核心页面 100% 被收录
- [ ] 首页首屏在 4G 网络下可交互时间（TTI）≤ 3s
- [ ] 运营团队可独立完成一次换季上新（含首页改版 + 新系列发布 + 新闻发布），全程不提交研发工单
- [ ] 全国门店信息准确率经零售运营抽检确认 ≥ 98%
- [ ] 零 P0 安全事故（无数据泄露、无页面被篡改、无服务不可用超 [TBD] 分钟）

## 2. 参考站点分析（PEACEBIRD 太平鸟）

### 2.1 参考站点是什么

PEACEBIRD 太平鸟的线上阵地是**分离的双站结构**，这一点对 FLY 的架构决策有直接影响：

| 站点 | 域名 | 定位 | 是否交易 |
|---|---|---|---|
| **品牌官网** | www.peacebird.com | 极简单页，核心是公司简介、品牌矩阵、门店网络、品牌价值主张 | ❌ 不交易 |
| **电商站** | shop.peacebird.com | 商品列表/详情/购物车/下单，美元定价，偏海外独立站 | ✅ 交易 |

**FLY 一期对标的是前者（品牌官网），不是后者。**

### 2.2 太平鸟官网的形态拆解

| 维度 | 太平鸟做法 | 观察 |
|---|---|---|
| 首页 | 全屏大视觉，极简导航，文字与图片强对比 | 品牌调性优先于信息密度 |
| 品牌内容 | 公司简介、品牌矩阵（女装/男装/LEDIN 乐町/MINI PEACE 童装） | 以"品牌矩阵"讲清业务版图 |
| 产品呈现 | 以系列/大片为主，非 SKU 列表 | 编辑感强，弱化货架感 |
| 门店 | 全国 3373 家门店、覆盖 305 个城市 `[引自公开资料·引用前需核实]` ，作为品牌实力背书 | **门店规模本身就是品牌资产** |
| 品牌主张 | 2025 年确立「悦享品质时尚」核心价值 + 「积极进取」调性 | 有清晰、可复述的一句话主张 |
| 视觉风格 | 大图/视频、留白、克制的动效 | 高制作门槛，依赖素材产能 |

### 2.3 我们学什么 / 不学什么

**✅ 要学的（Copy）**

1. **官网与电商分离**——内容归内容、交易归交易。避免官网被 SKU 表格和促销标签淹没。
2. **品牌叙事优先于货架**——产品以"系列 + 大片"呈现，而不是"分类 + 价格 + 库存"。
3. **门店作为品牌资产展示**——门店数量与覆盖面本身就是信任状，不只是工具页。
4. **一句话品牌主张贯穿全站**——所有内容围绕一个可复述的核心主张。
5. **极简导航**——主导航不超过 5 项，减少决策成本。

**❌ 不学的（No Copy）**

1. **不学"极简到没内容"**——太平鸟官网信息量极低（近乎单页），依赖其在国内已有的巨大品牌知名度。FLY 作为品牌官网建设期，需要**更多可被搜索引擎收录的内容页**（关于我们、产品系列、新闻），否则 SEO 冷启动无从谈起。
2. **不学"无门店地图"**——太平鸟官网只报数字不给地图。FLY 门店数量远小于太平鸟，**"能查到具体在哪"比"有几千家"更有用**，因此地图页是必备项。
3. **不学"纯静态不可运营"**——太平鸟官网更新依赖研发。FLY 一期即建设 CMS，否则每个换季都要发版。
4. **不学"忽略 SEO"**——太平鸟官网是 hash 路由 SPA（`#/`），对搜索引擎不友好。FLY 前台采用 **SSR**，这是我们有意识的差异化改进点。

> **一句话结论**：学它的**品牌叙事逻辑与克制感**，不学它的**内容贫瘠与技术债**。

## 3. 用户与角色

### 3.1 前台访客（C 端）

官网无登录、无会员，所有访客为匿名。按访问意图分为三类：

| 角色 | 特征 | 核心诉求 | 典型路径 |
|---|---|---|---|
| **V1 潜在顾客（主力）** | 通过社交内容/朋友推荐/搜索首次接触 FLY | 快速判断"这个品牌是什么风格、值不值得关注" | 首页 → 关于 FLY / 产品系列 → 门店查询 |
| **V2 既有顾客** | 已在门店购买过，回来了解新品 | 看当季有什么新系列、新店开在哪 | 首页 → 品类页 → 系列 → 款式详情 → 门店查询 |
| **V3 行业/合作方** | 媒体、博主、商场招商、供应链合作伙伴 | 了解品牌实力、门店规模、合作方式 | 首页 → 关于 FLY / 发展历程 → 联系我们 |
| **V4 求职者** | 通过招聘信息或口碑找过来 | 了解团队文化、判断值不值得投简历 | 首页 / 搜索 → 招聘 → 社会招聘 / 校园招聘 |

> **用户研究说明**：以上画像为基于业务常识的**假设画像（Proto-persona）**，尚未经过真实用户访谈验证。建议在首版上线后补充 8–10 位真实顾客的访谈，验证"访客到底是来看设计还是来找门店"这一核心分叉——它直接决定首页信息权重。此项列为 **第 11 章 R4 风险**。

### 3.2 后台操作角色（B 端）

采用轻量 RBAC，一期三种角色，不做按钮级细粒度授权。

| 角色 | 职责 | 可访问模块 | 权限边界 |
|---|---|---|---|
| **R1 超级管理员** | 系统配置、账号管理、全量数据 | 全部模块 | 可创建/停用账号、分配角色；可删除内容 |
| **R2 内容运营** | 首页装修、专题页与新闻发布、关于我们/招聘页面维护、留言处理、**全站图片素材管理** | CMS 装修、内容管理、留言管理、素材库 | 可发布/下线内容；可管理**全站图片素材**（含商品/系列/门店图片，经 FR-B16 素材库复用）；**不可**修改商品与门店的**结构化主数据字段**（名称、品类归属、地址、营业时间、库存等，仍归 R3）；留言人的手机号/邮箱**默认脱敏**，明文仅超管可见（见 FR-B19） |
| **R3 商品门店运营** | 品类下系列与款式管理、热门标记设置、门店信息维护、库存查询 | 商品系列管理、门店管理、库存查询 | 负责商品与门店的**结构化主数据**（名称/品类/价格类/地址/营业时间/库存等）与上下线；**不可**修改首页装修与发布新闻；其图片素材与 R2 共用 FR-B16 素材库维护 |

> **设计原则**：按"谁生产内容，谁维护内容"划分，避免多人共改首页导致互相覆盖。如需更细粒度（如"只能改自己城市的门店"），二期再评估。

### 5.3 URL 规范（SEO 关键约束）

| 规则 | 要求 | 原因 |
|---|---|---|
| 静态化路径 | 使用 `/products/men/2026aw-urban` 语义化路径，**禁止** `/#/products?id=123` | hash 路由无法被搜索引擎正常抓取（太平鸟官网即此问题） |
| 小写 + 连字符 | 全部小写，单词间用 `-` | 统一规范，避免大小写重复收录 |
| 层级 ≤ 4 层 | 款式详情最深：`/products/men/2026aw-urban/FLY26AW-CO001` | 层级过深影响权重传递 |
| 品类路径固定 | 三个品类与热门推荐的路径**写死不可改**：`/products/men`、`/products/women`、`/products/kids`、`/products/hot` | 路径变更会导致已收录链接失效 |
| 唯一性 | 一个 URL 唯一对应一个资源，禁止多 URL 同内容 | 避免重复内容惩罚 |
| 规范标签 | 每页输出 `<link rel="canonical">`；款式若同时归属热门推荐，canonical 指向品类下正式地址 | 明确首选版本，避免重复收录 |
| 服务端渲染 | 所有内容页 HTML 必须在服务端返回完整正文 | 见 NFR-2 |
| 路由优先级 | `/products/hot` 必须优先于 `/products/:category` 匹配，避免 `hot` 被当作品类名解析；`/api` 层同理 | 防止热门推荐页被品类路由吞掉 |

> **这是一期技术选型为 SSR 的核心理由**：若采用纯 SPA，第 1.3 节 G1「品牌词可检索、页面被收录」这个目标几乎不可能达成。

### 6.3 F3 产品中心

**定位**：产品以"品类 × 系列 + 大片"呈现，**不是电商货架**。这是本 PRD 与常规电商 PRD 最大的差异点，请研发与设计特别注意。

> **v1.1 变更**：新增**品类维度**（男装/女装/童装）作为产品的组织骨架，系列归属到品类之下；原「热销款式」因官网无销量数据，改为「**热门推荐**」，由运营人工打标。

#### 信息组织方式（v1.1）

```
品类 Category（男装 / 女装 / 童装）
   └── 系列 Collection（如 2026 秋冬「城野机能」）
         └── 款式 Item（款号 + 多图 + 面料 + 配色）

热门推荐 /products/hot  ←  跨品类、跨系列的「人工打标」聚合（不是销量排行）
```

| 层级 | 说明 | 约束 |
|---|---|---|
| 品类 Category | 固定三项：男装 / 女装 / 童装。后台**不提供自由增删**（涉及导航与 URL 结构，需走变更） | 枚举值 |
| 系列 Collection | 必须归属**唯一**品类，URL 路径中包含品类 | 1 品类 : N 系列 |
| 款式 Item | 必须归属唯一系列，**继承其品类** | 1 系列 : N 款式 |
| 热门标记 `is_hot` | 款式级布尔标记 + 独立排序权重，由运营在后台手动设置 | 与品类解耦，可跨品类 |

> ⚠️ **"热销"改名的原因**：官网不做交易、没有销量数据，客观上不存在"热销"这一事实。v1.1 改为「热门推荐」，由运营人工打标，**语义表示"主推"而非"卖得好"**——既不误导用户，也不必伪造数据。

#### 信息粒度约定（关键）

| 展示项 | 是否展示 | 说明 |
|---|---|---|
| 系列故事 / 大片 / 视频 | ✅ | 核心内容 |
| 所属品类（男装/女装/童装） | ✅ | 面包屑、筛选与导航高亮依据 |
| 款名、款号 | ✅ | 便于门店查询与识别 |
| 面料成分、配色、版型描述 | ✅ | 体现品质感 |
| "热门"标记 | ✅ | 运营人工打标，前台展示"推荐"角标（**不展示任何销量数字**） |
| 参考价格 | ❌ | 不展示（避免渠道价格冲突） |
| 尺码、尺码表 | ❌ | 不展示 |
| 库存数量 | ❌ | **前台不展示**（后台查询工具内部使用，见 B5） |
| 加入购物车 / 立即购买 | ❌ | 无交易 |
| 商品评价 / 销量 / 销量排行 | ❌ | 无交易与登录态 |

#### 用户故事

- 作为**潜在顾客**，我希望按男装/女装/童装快速进入我关心的品类，以便不用在全部商品里翻找。

### 6.5 F5 新闻

**定位**：品牌动态与行业观点的内容阵地，是 SEO 长尾流量的主要来源。

> **v1.1 变更**：原「资讯 JOURNAL」改名为「**新闻**」，一级栏目下二级菜单固定为「**企业新闻**」「**行业资讯**」。

#### 二级栏目定义

| 二级菜单 | URL | 内容范围 | 内容示例 |
|---|---|---|---|
| 企业新闻 | `/news/company` | FLY 自身动态：新品发布、门店开幕、品牌活动、获奖、里程碑 | 「FLY 2026 秋冬系列发布」「FLY 深圳万象天地旗舰店开幕」 |
| 行业资讯 | `/news/industry` | 行业视角内容：趋势观察、面料科普、穿搭指南、可持续时尚 | 「2026 秋冬面料趋势观察」 |

> **为什么保留「行业资讯」**：纯企业新闻更新频率天然很低（月更甚至季更），栏目长期不更新会导致搜索引擎抓取频次下降、整站权重受损。行业资讯可由运营以较低成本稳定产出（建议月 2–4 篇），作用是**喂住爬虫、拉长尾流量**——这是内容型官网的常规打法。

#### 用户故事

- 作为**潜在顾客**，我希望看到品牌的活动与动态，以便了解品牌是否在活跃运营。

### 6.8 B1 CMS 可视化装修（后台核心）

## 7. 关键业务流程

### 7.1 换季上新流程（最高频，直接影响 G4 目标）

```
① 商品门店运营 在【B3 商品系列管理】新建系列
      ↓  填写系列名/季节/头图/系列故事，保存为 draft
② 批量导入或逐个新增款式（款号/主图/面料/配色）
      ↓  支持 Excel 批量导入
③ 校对后 将系列与款式置为 online
      ↓
④ 内容运营 在【B1 CMS 装修】编辑首页
      ↓  在"当季系列推荐"区块中选中新系列，调整区块顺序
⑤ 保存草稿 → 预览（预览链接带 token）
      ↓  品牌负责人确认视觉与文案
⑥ 点击发布 → 二次确认 → 上线
      ↓
⑦ 前台 5 分钟内生效，无需研发介入、无需重新部署
```

**目标 SLA**：全流程 ≤ 1 个工作日（其中 ④–⑥ 应在 30 分钟内完成）。

### 7.2 门店信息维护流程

```
① 零售运营提供门店清单（Excel：名称/省市/地址/电话/营业时间/类型）
      ↓
② 商品门店运营 在【B4 门店管理】批量导入
      ↓  系统自动调用地理编码 API 获取坐标
③ 逐一核对坐标（地图选点组件微调）
      ↓  坐标错误的门店必须重新拾取，禁止手工填
④ 置为 online → 前台地图与列表即时更新
      ↓
⑤ 门店变更（关店/搬迁/改电话）走同一流程，历史修改留痕
```

### 7.3 内容发布流程

```
草稿 →（可选：定时发布）→ 已发布 →（可选：下线）
                ↑                        ↓
            预览确认                  前台 404
```

- 所有发布动作记入操作日志（FR-B10 / FR-B55）
- 首页发布需二次确认（FR-B07）
- 支持回滚到最近 10 个版本中的任意一个（FR-B06）
- **"后台改完前台立刻显示"的实现方式**：后台修改经**发布**动作后，由 NFR-11 触发 CDN/页面缓存 purge，前台在**秒~分钟级**内更新；**不是"保存即生效"**——任何上线变更都必须走发布（含二次确认与可回滚），避免误改直接命中线上

### 7.4 门店库存更新流程

```
① 各门店/区域 按模板填报：款号 | 门店编码 | 数量 | 日期
      ↓
② 总部汇总 →【B5 库存查询】Excel 批量导入
      ↓  校验款号与门店编码存在性，失败则报错并指出行号
③ 系统按「款号 + 门店 + 日期」去重更新
      ↓
④ 后台可查；前台仅以"部分门店有售"定性提示（不显示数量）
```

### 9.3 关键架构决策与理由

| 决策 | 选择 | 理由 | 被否方案 |
|---|---|---|---|
| ADR-1 前台渲染方式 | **SSR** | 官网以内容获客为核心，SEO 是生命线；太平鸟官网 hash 路由 SPA 正是我们要规避的 | 纯 SPA（SEO 不可达） |
| ADR-2 前后台应用拆分 | **两个独立前端应用** | 官网要 SSR + 极致性能，后台要开发效率 + 组件丰富；混在一起两边都不讨好 | 单体应用 |
| ADR-3 后台不做 SSR | **纯 SPA** | 后台无 SEO 需求，SPA 部署简单、迭代快 | 后台也 SSR |
| ADR-4 首页内容来源 | **CMS 动态配置** | 换季上新是最高频动作，硬编码会导致每次改版都要发版（G4 目标） | 硬编码/配置文件 |
| ADR-5 地图服务 | **高德地图** | 国内合规、有审图号、地理编码准确，境外服务存在合规风险 | Google Maps / Mapbox |
| ADR-6 库存数据获取 | **手工录入 + Excel 导入** | 一期无交易、无 ERP 对接，实时同步投入产出比低 | ERP 实时对接 |
| ADR-7 数据库选型（v1.5） | **SQLite（async）** | 纯内容型官网数据量小、读多写少，单文件零运维、开箱即跑、备份即复制；ORM 已抽象，量级上来可平滑迁移 | PostgreSQL + Redis（重运维，本期无收益） |

| A6 | 库存数据一期依靠人工维护，不要求实时准确 |

## 附录 A：术语表

| 术语 | 说明 |
|---|---|
| SSR | Server-Side Rendering，服务端渲染。页面 HTML 在服务器生成后返回，利于 SEO 与首屏 |
| SPA | Single Page Application，单页应用。前端路由渲染，部署简单但 SEO 弱 |
| 品类 Category | 产品的第一级组织维度，固定枚举：男装 / 女装 / 童装。系列必须归属唯一品类，款式继承品类 |
| 系列 Collection | 产品的第二级组织维度，必须归属唯一品类；拥有独立 `slug`，用于 URL 路径 |
| 款式 Item | 产品的最小展示粒度，归属唯一系列，品类由系列继承；款号 `item_code` 全局唯一，用于 URL 与门店库存关联 |
| slug | URL 中的语义化短标识（仅小写字母/数字/连字符）。一经发布**不得修改**，确需改路径必须配置 301（FR-F77） |
| 热门推荐 Hot | 运营在后台**人工打标**的主推款式聚合位（`/products/hot`）。**不是销量排行**——官网无交易无销量数据（见 4.2 N12） |
| SPU / SKU | 本项目中**不使用**电商 SKU 概念；商品以「品类 Category + 系列 Collection + 款式 Item」三级组织 |
| CMS | Content Management System，内容管理系统。本文特指后台的可视化页面装修与内容发布能力 |
| GCJ-02 | 中国国家测绘局制定的地理坐标系（俗称"火星坐标"），高德/腾讯地图使用；区别于 WGS-84（GPS 原始坐标） |
| 审图号 | 地图审核批准号，国内合规地图服务必须展示 |
| MoSCoW | 优先级法：Must / Should / Could / Won't |
| LCP / CLS / TTI | 核心网页性能指标：最大内容绘制 / 累积布局偏移 / 可交互时间 |
