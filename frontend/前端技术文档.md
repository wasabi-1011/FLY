## 0. 一页结论

**官网前台（`frontend/web`）现状 = 首页 + 全量二级页面已按原型还原并全部打通（2026-09-09 完成），仅招聘页、门店详情、全站搜索与真实后端 API 接入仍在后续。**

- **已实现**：首页（吸顶导航 + 全屏轮播 + 当季系列 + 热门推荐 + 门店地图 + 新闻 + 五大栏目 + 页脚），React/Vite/React-Router，样式与交互主要来自原型移植。
- **已实现（2026-09-09 补，见《前台二级页面规划与元素规格.md》）**：`/products`（聚合罗列）、`/products/:category`（女/男/童品类页）、`/products/hot`（热门页）、`/news/company|industry` + 图文详情、`/stores`（门店大图联动）；导航/页脚/首页卡片已从锚点改为真实路由跳转。页面数据为静态示例（字段对齐后端接口）。
- **未实现（后续）**：`/about`…（关于FLY/品牌介绍/发展历程/联系我们）、招聘页、门店独立详情页、全站搜索、接入真实后端接口与 SSR。
- **关键差距**：package.json 标注「SSR 预留 / SEO 是关键」，但当前是**纯 SPA（BrowserRouter，无 SSR；SSR 仅为脚本占位、无实际代码）**。SEO 是 PRD 生命线（见审核报告），SSR 落地是二期核心工作。

**一句话**：先把二级页面用现有 SPA 方式做出来看到效果，再统一上 SSR 保 SEO。

### 1.4 已实现的关键技术点（供复盘）

- **原型 `docs/FLY官网_首页原型.html` → React 组件**的移植路径：样式类名一一对应进 `site.css`，JS 交互（轮播、地图）转成 React Hooks / 生命周期。
- **轮播**：`useState` 管理当前帧 + `setInterval` 自动播放 + 悬停暂停 + 指示点跳转（`Hero.jsx`）。
- **入场动效**：`IntersectionObserver` 进入视口给卡片加 `.in` 类触发 CSS 过渡（`Home.jsx` 热门卡片）。
- **地图**：`StoreEntry.jsx` 动态注入腾讯地图 JS，用 `MutationObserver` 清理「鉴权失败」提示条（避免遮挡底图；`KEY` 已拼入脚本 URL）。
- **响应式**：`site.css` 里 `@media` 处理移动端（汉堡抽屉、固定「查门店」按钮）。

### 2.2 各页面所需技术清单

#### ① 男装 / 女装 / 童装 品类页（`/products/:category`）
- **路由参数**：`react-router` 的 `useParams()` 读取 `category`（men/women/kids），驱动同一套组件复用。
- **数据请求**：引入数据层（fetch 或 axios + TanStack Query），调 `GET /api/products/{category}` 取「系列墙 + 热门推荐」。
- **布局参考**：复用首页 `coll-grid`（系列卡片）+ `hot-grid`（主推款式）结构与样式。
- **约束（N5/N12）**：不渲染价格/库存/销量字样；热门为运营人工标记，非销量排行。
- **路由优先级（审核报告 M10）**：React Router v6 按**静态段 > 动态段**自动排序，`/products/hot`（静态）优先级天然高于 `/products/:category`（动态），**无需关注注册顺序、也不会被吞**；保留独立静态路由即可。

#### ② 款式详情页（`/products/:category/:collection_slug/:item_code`）
- **路由三段参数**：category / collection_slug / item_code。
- **数据请求**：`GET /api/products/{category}/{collection_slug}/{item_code}`。
- **面包屑（审核报告 L3）**：页头必须显示「首页 › 产品 › 品类 › 系列名 › 款名」，可用 `react-router` 的 Link + 传入参数拼。
- **有货门店入口（F28/S3）**：调 `GET /api/stores/availability` 查「哪些门店有货」，前台仅定性提示（不显示数量）。
- **图片**：款式多图展示（`Item.images`），可做缩略图切换。

#### ③ 企业新闻列表 / 详情页（`/news/company`、`/news/company/:slug`）
- **列表**：`GET /api/news`（分页参数）→ 列表卡片，**必须分页或虚拟滚动**（审核报告 L4 同类约束思路，避免长列表直出）。
- **详情**：`GET /api/news/{category}/{slug}` → 富文本正文渲染。
- **富文本/安全**：正文为后端 HTML（已过 XSS 白名单，NFR-18），前端用 `dangerouslySetInnerHTML` 或安全渲染组件输出（**不要再二次拼接**）。
- **SEO**：详情页是最需收录的内容页，标题/描述/og 标签需随数据填充（见 §3 SSR）。
- 分类固定两项：`company`（企业新闻）/ `industry`（行业资讯）。

#### ④ 关于我们 固定页（关于FLY/品牌介绍/发展历程/联系我们）与招聘页
- **数据请求**：`GET /api/pages/{*path}`（通配 slug，审核报告 L5 已改为 `{*path}`）取固定页富文本正文。
- **联系我们**：除展示外，还要**留言表单** → `POST /api/contact`（含验证码/限频；邮箱可混淆渲染但正文 SSR，M6）。
- **招聘**：两页为**静态介绍**（人才理念 + 岗位方向 + 投递邮箱），无职位列表/在线投递（Non-goal N13）。内容由后台固定页维护。

#### ⑤ 门店列表 + 地图 + 详情
- **列表 + 地图**：`GET /api/stores` + `GET /api/stores/cities`（城市分组 + GCJ-02 坐标）。地图用**腾讯地图 JS API（GL JS）**（已确认全站统一腾讯，依据已申请腾讯地图 API；与 PRD 默认假设高德不一致属可控偏差，坐标仍为 GCJ-02 无需转换）。
- **详情页**：`GET /api/stores/{store_id}`，展示营业时间/今日营业状态（L1）、有货提示；**独立可收录 URL**（L2）。

#### ⑥ 全站搜索
- `GET /api/search?q=`，结果页 + 高亮命中词；SPA 内可用 query string 传参。

## 4. 二期：SSR 落地建议（对齐 PRD「SEO 关键」）

- **现状**：`package.json` 仅有 `dev:ssr` / `build:ssr` 两个脚本名，但其指向的 `server.js` / `build-server.js` **实际不存在**（已代码核验）；当前为纯 Vite SPA（BrowserRouter），SSR 无任何脚手架，二期需**从零搭建**。
- **技术选型**（PRD 定调 SSR）：
  - 主流选项：**Next.js**（迁移成本高，重构路由/数据层）或保持 **Vite + 自建 Node SSR**（复用现有 React 组件与路由，改动小）。
  - 建议：无论 **Next.js** 还是 **Vite 自建 SSR**，均从零搭建（当前无 SSR 代码）。**Next.js** 更贴合「SEO 是关键」的长期目标；若求快可先用 Vite 自建 SSR 过渡。
- **每条内容页要 SSR 完整输出**正文（审核报告 M6：仅邮箱字段可混淆），新闻/款式/固定页详情尤其重要。
- **结构化数据（JSON-LD）**：审核报告将 NFR-13/FR-F40 提为 **S 级**，详情页需输出（组织/文章/产品/门店结构化数据）。
- **性能指标（M2）**：首屏 **LCP ≤2.5s**（4G）、并发 ≥500 P95≤2s。
- **下线内容**统一返回 **404 + noindex**（审核报告 S7），不混用 410。

## 5. 建议的开发优先级

1. **先做导航二级页骨架**（复用 SiteNav/SiteFooter + 现有样式）+ 接入后端接口，让男装/女装/童装、企业新闻、关于FLY能真的看到内容。
2. **再做固定页 + 留言表单**（关于我们/联系我们，打通 `POST /api/contact`）。
3. **门店详情 + 全站搜索**补充完整。
4. **最后统一上 SSR** 保 SEO（若确认上 Next.js，则步骤 1-3 的页面直接用其数据获取方式重构一次）。
