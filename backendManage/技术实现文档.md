## 0. 技术栈总览

| 层 | 选型 | 说明 |
|----|------|------|
| 前端渲染 | 原生 HTML + CSS + 无框架 JS（当前为单文件静态原型） | 骨架为**若依 Vue 风格**：暗色侧栏 `#001529` / 内容区 `#f5f7fa` / Element 蓝 `#409EFF` |
| 前端框架（落地目标） | React + Ant Design（对齐 PRD 4.1 与后台技术方案） | 当前原型是静态演示，正式开发按此演进 |
| 状态管理 | TanStack Query + Zustand（后台技术方案已定） | 服务端数据用 Query 管理缓存/失效，本地 UI 态用 Zustand |
| 路由 | React Router v6 | 子菜单数据视图路由；RBAC 用路由守卫 |
| 后端 API | 复用 `D:\FLY网站\backend` 的 FastAPI，前缀 `/api/admin` | 接口已带 RBAC，前端直接调用；例外：`/api/stores/cities` 为**公开只读**接口（供前台门店地图使用，无 RBAC，见 §2） |
| 地图 | **腾讯地图** JS API（GL JS，`map.qq.com/api/gljs`） | 与前台统一为腾讯；PRD 默认假设为**高德**，已据已申请 API 调整为腾讯（偏差可控，详见技术方案 §1）；GCJ-02 火星坐标，无需转换 |
| 富文本 | **wangeditor**（落地时替换原型 `execCommand`） | 新闻/资讯正文以 HTML 存储，出库前做 XSS 清洗（以服务端净化为准，见 §9） |
| 图表 | 前端图表库（ECharts 或 Recharts） | 仪表盘与数据看板展示 |

> RBAC 三角色（以《后台管理系统-技术方案》§4 为权威，本文档不再另定义）：`SUPER_ADMIN`（全部）/ `CONTENT_OPS`（内容运营：首页装修、企业新闻、固定页、联系留言、全站图片素材）/ `MERCH_STORE_OPS`（商品门店运营：产品/系列、款式、门店主数据、库存）。

## 1. 门店列表

### 1.1 功能范围
- 门店 CRUD（新增 / 编辑 / 删除 / 状态切换：营业中 / 待审核 / 已下线）。
- **腾讯地图点选经纬度**（新增门店弹窗内嵌地图，点击/拖拽回显 GCJ-02 坐标）。
- 上下线即时反映前台门店地图；批量导入（技术方案 B4 约定，二期可延后）。
- 筛选：门店名称、城市、状态；分页。

### 1.2 关键实现技术
- **列表页**：表格 + 筛选栏（受控组件）+ 分页；TanStack Query `useQuery(['stores', {page, city, status, name}])` 拉取，`keepPreviousData` 保证翻页不闪烁。
- **新增/编辑**：弹窗（Modal）+ 表单校验（名称必填、坐标非空、地址长度）；提交 `POST/PUT /api/admin/stores` 后 `invalidateQueries(['stores'])` 刷新列表。
- **地图点选（核心难点）**：
  - 引入腾讯地图 GL JS（`v=1.exp&key=KEY`），`TMap.Map` 初始化，中心默认当前城市或上次坐标。
  - `map.on('click', e => e.latLng)` 取点 → `TMap.MultiMarker` 放置标记 → 经纬度回写到只读输入框（6 位小数）。
  - 编辑态：初始 `setCenter(lat,lng)` + 预置标记。
  - **无 Key/离线降级**：原型用 SVG 模拟地图（点击 + 指针拖拽 pin），填 `TENCENT_MAP_KEY` 后自动切真实地图；生产环境应固定为真实地图并配好 Key。
- **删除**：二次确认（Popconfirm）；采用逻辑删除，标记 `is_active=false`（对齐后端语义，具体以 `app/schemas` 的 Store 模型为准）。
- **坐标约定**：全局 GCJ-02，后端存经纬度双字段，前端只需回显，无转换。

### 1.3 数据字段（对齐后端 schema）
`id, name, city, address, lat, lng, status, is_active, created_at, updated_at`
> 批量导入（B4）字段约定以 `app/schemas/` 与 PRD FR-B31~B37 为准。
> 门店状态模型（`status` 枚举 + `is_active` 布尔）以 `app/schemas/store.py` 为唯一权威，前端不自行定义状态枚举；原型暂用 `status` ∈ {营业中, 待审核, 已下线}。

### 1.4 接口
`GET /api/admin/stores`（列表，支持 name/city/status 筛选 + 分页）· `GET/POST/PUT/DELETE /api/admin/stores/{id}`
> 文件上传补 `POST /api/admin/upload`（技术方案 §8，尚未在后端实现），用于门店图等。

## 2. 城市分组

### 2.1 功能范围（门店管理下的"按城市聚合"视图，非独立模块）
- 作为**门店管理**的视图/筛选维度：按城市聚合门店列表（北京/上海/广州/深圳/成都/杭州…）。
- 每个城市作为分组标题，其下展示该城市门店。
- 仅前端聚合展示，不引入独立数据模型；城市来源以门店 `city` 字段为准（见 §2.2 数据来源）。

### 2.2 关键实现技术
- 数据来源（二选一，推荐后端接口）：`GET /api/stores/cities`（**公开只读接口，无 RBAC**，由后端聚合返回 `{city, stores[]}`）或前端对门店列表做 `groupBy(city)`。
- 渲染：分组列表（不是表格）——城市卡片/折叠面板（Collapse）+ 每城市下门店迷你信息（名称、地址、状态、坐标）。
- 选型建议：用 `Array.prototype.reduce` 按 city 分组，得到 `{ city: string, stores: [] }[]`；配合 React 列表渲染 + 城市计数徽标。
- 交互：城市可展开/收起（默认展开第一个）；点击门店可跳转编辑弹窗或门店详情。
- 与地图联动（可选增强）：左侧城市分组、右侧地图聚合标记 `MultiMarker`，点分组高亮对应城市门店。

### 2.3 接口
`GET /api/stores/cities`（城市及其门店，**公开只读，无 RBAC**，详见技术方案 §6）· 或复用 `GET /api/admin/stores` 后前端分组。

## 3. 款式列表

### 3.1 功能范围
- 款式（单品）列表展示：**主图（image，v1.1 新增列；v1.3 起列内显示「查看图片」链接、点击弹大图，无图显示"未设置"）**、分类（男装/女装/童装）、系列、价格、库存、状态（在售/草稿/已下架）。
- 查看款式详情 / 编辑入口 / 上下架切换。
- 筛选：款式名称、分类、状态；分页。

### 3.2 关键实现技术
- 与门店列表同构：Query + 筛选 + 表格 + 分页。
- 上下架：`PUT /api/admin/items/{id}` 更新 `is_active/status`，下线后前台款式 404（对齐后端语义）。
- 价格展示：后端以**整数分**存储（`items.price` 为 int），前端统一以「元」展示并千分位格式化（`¥1,299`），换算以后端 schema 为准，避免浮点误差。
- 库存：B5 约定前台只显示「部分门店有售」定性，后台款式列表可显示总库存量（内部工具，二期优先）。
- 状态标签映射：在售→绿、草稿→橙、已下架→灰（复用现有 tag 样式体系）。

### 3.3 接口
`GET /api/admin/items`（列表，category/name/status 筛选）· `GET/PUT /api/admin/items/{id}`
> 款式归属系列：`collections`（产品系列）→ `items`（款式）多对一，见「款式管理」。

## 4. 款式管理

### 4.1 功能范围
- 款式 CRUD（新增/编辑/删除）+ 分类维护（男装/女装/童装）- **分类维护指款式归属的品类**。
- 系列（collection）CRUD 与维护（技术方案 B3：系列 CRUD、热门标记 `is_hot`、上下线、排序）。
- 款式挂系列：新增/编辑款式时选择所属系列。

> 说明：本系统「款式列表」= 列表+详情展示入口；「款式管理」= 完整的款式、系列、分类维护。
> 你同时在需求里列「款式列表」与「款式管理」，实现上两者共用同一套 store/API，列表偏查看、管理偏编辑。

### 4.2 关键实现技术
- 款式管理页：列表 + 新增/编辑弹窗 + 系列管理（子页或 Tab）。
- 系列管理：系列 CRUD（名称、所属分类、头图、状态、排序、`is_hot` 热门标记）。
  - `is_hot` 人工标记，用于前台热门系列排序（PRD 6.10）。
  - 头图用上传接口 `POST /api/admin/upload`，返回 URL 存系列字段。
- 表单：
  - 款式：名称、分类、系列（下拉，加载 `collections`）、价格、库存、状态、**主图 `image`**（v1.1 新增；v1.3 交互：弹窗内点「添加图片」打开系统文件选择器选本地图 → `fileToDataUrl` 等比压缩（最长边 1600、JPEG 0.85，canvas 不可用时回退原图）为 dataURL 实时预览；同时保留「粘贴图片链接」入口供图床/外链；列表列渲染为「查看图片」链接，点击 `openImgViewer` 弹大图，不直接铺图）、描述。
  - 分类：固定枚举男/女/童装（可用常量表，避免魔法字符串）。
- 校验：名称必填、价格 ≥ 0、库存 ≥ 0、状态合法；错误用表单校验（Ant Design Form rules）。
- 删除保护：系列下若有款式，应阻止删除或提示先清空（外键约束兜底）。

### 4.3 接口
- 系列：`GET/POST/PUT/DELETE /api/admin/collections`、`/collections/{id}`
- 款式：`GET/POST/PUT/DELETE /api/admin/items`、`/items/{id}`
- 上传：`POST /api/admin/upload`（待后端补）

## 5. 新闻管理

### 5.1 功能范围
- 企业新闻 CRUD + **富文本编辑发布**（核心需求）。
- 分类：品牌动态 / 门店开业 / 社会责任 / 行业资讯。
- 状态：已发布 / 草稿 / 已下线（发布后前台可见，下线前台隐藏）。
- 作者、发布时间；发布与存草稿两种保存动作。角色：`CONTENT_OPS` + `SUPER_ADMIN` 可见可操作。

### 5.2 关键实现技术
- **富文本编辑器**（落地替换原型的 `document.execCommand`）：
  - 选型：**wangeditor**（中文生态，已定）。提供工具栏：粗体/斜体/下划线/列表/清除格式（原型已含对应按钮）。
  - 正文以 **HTML 存储**；**安全**：出库渲染前做 XSS 清洗（白名单标签属性，如只允许 p/h/h2/ul/ol/li/b/i/u/strong/a/img）。**净化以服务端为主**（后端出库时用 DOMPurify / sanitize-html 处理，白名单同上），前端 `dangerouslySetInnerHTML` 前再做一次净化为辅。
- 发布/存草稿：区别在 `status` 字段（published/draft）。发布校验：标题、正文必填；标题长度限制（如 ≤ 120 字）。
- 列表：状态标签 + 分类筛选 + 分页；「新增/发布」按钮滚动聚焦编辑区。
- 作者：默认取当前登录用户名（从 RBAC session 读）；发布时间 = 发布动作时刻，草稿不显示。
- 封面上传（可选）：用 `POST /api/admin/upload`，存在 news 封面字段。

### 5.3 接口
`GET/POST/PUT/DELETE /api/admin/news`、`/news/{id}`
> 发布/下线语义（status 字段 vs 专用动作端点）以 `app/routers/admin/news.py` 实际实现为准，前端按后端返回的状态渲染，不自行假设。

## 7. 网页管理 · 首页轮播图（v1.1 新增）

> 模块入口：侧栏「运营 → **网页管理** → **首页轮播图**」；对应官网首页 Banner 轮播位（PRD B1 首页装修的最先落地板块）。
> 角色权限：`SUPER_ADMIN`、`CONTENT_OPS`（内容运营负责全站图片/首页内容，符合角色矩阵；`MERCH_STORE_OPS` 不可见）。
> 数据模型归属：**原型以独立 `banners` 演示数组简化实现**；正式落地对齐后台技术方案 B1「首页装修（CMS）」——首屏轮播作为 home 页的轮播区块（`frames` 多帧：图片/视频+叠加文字+启停+排序），经区块编辑 + 版本发布生效（见 7.4 与《后台管理系统-技术方案》6.8）。

### 7.1 功能范围
- 首页轮播图列表：图片缩略图（**点击弹大图查看**，v1.3）、标题、跳转链接、排序、状态（显示中/隐藏）、更新时间。
- 编辑 / 新增：图片、标题、跳转链接、排序、状态。
- 删除（带确认）；筛选：标题关键词、状态；排序字段决定前台轮播先后（数字小在前）。
- 状态=隐藏 的轮播不出现在前台首页轮播位。

### 7.2 关键实现技术
- 复用**通用 CRUD 表格机制**（与款式/系列/账号/角色同一套 `tableConfig → openTableModal → saveTableRow`），扩展了 `type:'img'` 字段：
  - **取图（v1.3，取代手填 URL）**：弹窗内点「添加图片」→ 触发隐藏的 `<input type="file" accept="image/*">` 调起**系统文件选择器** → `fileToDataUrl()` 用 `FileReader` 读取并经 `<canvas>` 等比压缩（最长边 1600px、`image/jpeg` 0.85；无 canvas 环境回退原 dataURL）→ `.img-prev` 实时预览；同时保留「粘贴图片链接」次级入口（`http(s)`），供图床外链场景；「移除图片」可清空。
  - 列表展示（v1.3）：**款式等"主图"列不再渲染图片本体**，改为「查看图片」链接（`imgLinkCell()`，无图显示"未设置"）；轮播列表仍以小尺寸缩略图示意（`imgThumb()`：`http(s)`/`data:` 叠加渐变背景，加载失败或空值自动回退渐变色占位，不裂图）。任一图片元素点击均经行事件委托调用 `openImgViewer()` 弹大图层（加载失败显示占位提示）。
  - 图片值（URL 或 dataURL）存于元素 `data-img` 属性；`rowDataOf` 读取该属性回填编辑表单（避免把显示文本当 URL）。dataURL 仅存于当前页面内存/演示行，不持久化，刷新即还原——与全站演示数据一致。
  - 真实后端落地：dataURL 仅原型演示；正式环境改由「素材库 / 上传」接口（`POST /api/admin/upload`）返回可访问 URL 回填。
- 转义与安全：标题/链接等用户输入经 `esc()` 后再入 `innerHTML`（对齐 §9 安全要求）。

### 7.4 接口（正式落地对齐后台技术方案 B1）
- 后端不以独立 `/banners` 表实现，而由**首页装修（CMS）**承载：`home` 页面含"首屏轮播"区块，区块 `config_json` 内为 `frames[]` 多帧（每帧 `image`/`link`/叠加文字/启停/排序）；编辑经"草稿 → 预览（token 链接）→ 二次确认发布"生效并支持版本回滚（FR-B02/B04/B05/B06/B07）。
- 后端现有枚举参考：`app/enums.py` 首页区块类型含 `IMAGE_BANNER`（图文 banner）；`app/seed.py` 首页 seed 即以 `frames[]` + `IMAGE_BANNER` 演示。
- 图片上传统一走 `POST /api/admin/upload`（`UPLOAD_MAX_MB` 限制，仅 jpg/png/webp，禁 SVG/脚本）。
- 本原型模块的交互（选图/标题/链接/排序/启停）即 B1 轮播帧编辑器的最小闭环演示，落地时把增删改映射到区块帧编辑即可，交互与校验可直接复用。

### 7.5 端到端打通（v2.0 已实现：后台 → fly.db → 官网首页）

> 7.1–7.4 描述的是原型自身能力；7.5 记录**真实链路已经跑通**的部分（本次实现）。

**链路**：后台保存 → `PUT /api/admin/home/carousel` → 生成首页新版本并**立即发布** → 前台 `GET /api/content/home` 读到新帧 → `Hero` 渲染。中间无任何人工步骤。

**后端新增（`backend/app`）**

| 新增 | 路径 | 说明 |
|---|---|---|
| 图片上传 | `routers/admin/upload.py` → `POST /api/admin/upload` | `CurrentContentOps` 鉴权；落盘 `backend/uploads/`，返回 `{"url": "/uploads/<uuid>.<ext>"}`；仅 jpg/png/webp/gif，上限 `UPLOAD_MAX_MB`(10MB) |
| 轮播读取 | `routers/admin/home.py` → `GET /api/admin/home/carousel` | 取 home 当前版本 `FULLSCREEN_VISUAL` 区块，归一化输出 frames |
| 轮播写入 | 同上 → `PUT /api/admin/home/carousel` | 以当前版本 blocks 为底新建 `PageVersion`，替换轮播区块 `config_json`，置 `current_version_id` + `status=published`，写审计日志 |
| 静态挂载 | `main.py` | `/uploads`（backend/uploads）、`/admin`（backendManage 单页，`html=True`）；根路径 `/` 返回导航信息，不再 404 |

**前端改造**

- **后台原型 `index.html`**：轮播视图顶部新增「后端连接条」——
  - 未连接 / `file://` 打开：显示"未连接后端（本地演示）"，行为与 v1.3 完全一致，**离线可用不受影响**；
  - 点「连接后端」：`POST /api/admin/auth/login`（OAuth2 form）取 JWT 存 `localStorage.fly_admin_token`；此后进入列表即自动拉取，新增/编辑/删除每次操作全量 PUT 并发布（toast 提示版本号）；
  - 已连接时「添加图片」走 `POST /api/admin/upload` 取真实 URL（不再是 dataURL）；401 自动登出并提示重连。
- **前台 `Hero.jsx`**：`useEffect` 拉 `/api/content/home` → 取 `FULLSCREEN_VISUAL.config_json.frames` → **仅渲染 `active !== false` 的帧**；`image` 作背景，`link` 渲染"了解更多"按钮；**请求失败或无帧自动回退本地兜底帧**，后端不可用时首页不会白屏。
- `frontend/web/vite.config.js` 新增 `/uploads` → `localhost:8000` 代理（开发态图片可显示）。

**frames 数据契约**（后台与前台的唯一约定，新增字段向下兼容 `layers[]`）

| 字段 | 说明 |
|---|---|
| image | 图片 URL（`/uploads/...` 或外链），空则用 CSS 兜底图 |
| kicker / title | 眉标 / 主标题 |
| **sub** | **轮播副标题**（显示在标题正下方）。后台新增时默认值 `"穿出自我，随心而飞"`，可改；前台按内容自动选样式（含中文用 `.frame-cn` 衬线字距，纯英文用 `.frame-sub` 宽字距） |
| cn | 中文副标（兼容旧 `layers[]` 结构，与 sub 不同时额外渲染一行） |
| link | 「了解更多」按钮跳转地址。**空则前台回退 `/products`，按钮恒定显示**（v2.1：修复新增帧无按钮的问题） |
| active | false = 隐藏，前台不渲染 |

> v2.1 兜底规则：帧同时缺 sub 与 cn 时，前台渲染默认副标题「穿出自我，随心而飞」，避免首屏文案过空。

**轮播数据在数据库里的位置（v2.1 补充）**

```
pages(slug='home').current_version_id        ← 当前生效版本指针
  └─ page_versions(id=…, version_no=…)       ← 每次后台保存新建并发布一个版本（可回滚）
       └─ blocks(type='FULLSCREEN_VISUAL').config_json.frames   ← 轮播帧数组
```

- 图片**本体不入库**，只存路径字符串 `/uploads/<uuid>.jpg`，文件落在 `backend/uploads/`。
- 因为每次保存都新建版本，`blocks` 表会存在多份历史轮播数据（旧版本不删），**只有 `current_version_id` 指向的那份会显示在前台**。用数据库工具查看时若"没变化"，先刷新查询结果，或确认看的是不是最新版本对应的 block。
- 一键查看：`cd backend && .venv\Scripts\python.exe 查看首页轮播.py`（`--all` 额外列出所有历史版本），会打印 pages / page_versions / blocks 三级定位与每帧字段、并校验图片文件是否真实存在。

**本地联调步骤**

1. `cd backend && .venv\Scripts\activate && python -m app.seed`（首次）→ `uvicorn app.main:app --port 8000`
2. 打开 `http://localhost:8000/admin/index.html` → 运营 → 网页管理 → 首页轮播图 → 点「连接后端」（admin / admin1234）
3. `cd frontend/web && npm run dev` → 打开 `http://localhost:3000`，改一条轮播刷新即可看到变化

## 8. 数据流与鉴权（横切关注点）

- **鉴权**：前端路由守卫按角色显隐菜单/入口（已原型化 `data-roles`）；后端每个接口 `require_roles` 兜底（越权 403，对齐 FR-B57）。
- **登录**：`POST /api/admin/auth/login`（对齐技术方案 §1/§6）返回 token + 角色；**Token 存储优先采用 httpOnly + SameSite Cookie**（由后端 Set-Cookie 下发，前端不接触原始 token）；若一期受限需暂用 localStorage，须标注 XSS 风险并限期迁移 → 路由守卫 + Query 统一注入 Authorization。
- **数据失效**：任意增删改后 `invalidateQueries` 对应列表，保证列表与详情一致。

## 9. 安全与合规

- 富文本 XSS 清洗（见 §5.2）；上传接口（`POST /api/admin/upload`）**禁止 SVG/含脚本 HTML**，仅允许图片类型（jpg/png/webp），限制大小（对齐 `UPLOAD_MAX_MB`），生成唯一文件名并做 MIME 校验。
- 门店/新闻经纬度与内容字段：文本 length 限制防注入；统一 DB 参数化查询（后端职责）。
- 涉及内容公开的新闻/门店上下线动作须写入**操作日志**：见《后台管理系统-技术方案》B6（操作日志 / 登录日志，`/admin/logs`），由后端 `app/routers/admin` 记录，前端仅触发动作、不实现日志 UI。
