## 1. 门店列表（v2.6：接库 + 腾讯地图点选）

### 1.1 功能范围
- 门店 CRUD（新增 / 编辑 / 删除），状态三态：在线 `online` / 待审核 `draft` / 下线 `offline`。
- **腾讯地图点选 + 地址解析**：弹窗内嵌地图，填地址 → 后端地理编码 → 坐标回写 → 可在地图上点选微调。
- 上下线即时反映官网门店地图（公开接口只返回 `online`）。
- 筛选：关键词（名称 / 城市 / 地址）、城市（下拉动态）、类型、状态；分页 `limit` / `offset`。
- 删除前提示连带清除的库存条数（`stock_count`），避免静默连删。
- **Non-goals**：门店批量导入（二期）、库存管理 UI（B5，二期）、门店详情前台路由、路线规划与导航。

### 1.2 关键实现技术
- **列表渲染**：`renderStoreRows()` + `storeRowCache`（`data-pid` → 门店对象）；编辑/删除直接取对象，不再从 DOM 反查文本（避免字段丢失与转义问题）。
- **接库**：登记 `API_LOADERS.stores` / `API_LOADERS.citygroups`，继承全局唯一连接条（v1.7）。`loadStores()` 带筛选参数请求，**无筛选时回写 `storeCache`** 供城市分组与仪表盘复用。
- **地图（核心难点，v2.6 定稿）**：
  - Key 从 **`window.__FLY_TMAP_KEY__`** 读取（代码里不写死明文；前端 Key 可被嗅探，必须配 Referer 白名单）。
  - **L1 真地图**：腾讯 GL JS（`libraries=service`），`TMap.Map` + `MultiMarker`；点击取点 → 回写 6 位小数坐标 → 地址栏为空时静默逆地理回填省 / 市 / 区。
  - **L2 手工坐标**：地图不可用时切 SVG 示意框，**坐标输入框由 `readonly` 放开为可编辑**，可粘贴或从坐标拾取器复制。
  - **L3 阻断保存**：坐标为空不放行（提示"请先确定门店坐标"）。
  - **地址解析**：优先 `POST /api/admin/stores/geocode`（服务端 Key，不外泄）；返回 **501**（未配置 Key）时退回前端 `TMap.service.Geocoder`；都不可用则引导手工录入。解析可信度 `reliability ≤ 7` 提示人工复核。
  - **演示地图不预填坐标**：打开弹窗只放置 pin，用户点击 / 拖拽后才写入，防止"没选点也能保存"。
- **坐标约定**：全局 **GCJ-02**，后端存 `lng` / `lat` 双字段，腾讯底图原生 GCJ-02，**全程无坐标转换**。

### 1.3 数据字段（对齐后端 `app/schemas/store.py`）
`id, name, province, city, district, address, lng, lat, phone, business_hours, store_type(FLAGSHIP/STANDARD/OUTLET), images(JSON), status(online/draft/offline)`
- 后台列表出参额外带 `stock_count`（仅 `/api/admin/stores` 填充，公开接口为 `null`）。
- **不存在 `created_at` / `updated_at`**：v2.6 已移除列表「更新时间」列（早期文档写的该字段后端并没有）。
- 城市下拉来自 `GET /api/stores/cities`（库里实际 8 个城市 20 家门店，早期写死的 6 个不够）。

### 1.4 接口

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/admin/stores` | 列表，支持 `keyword` / `city` / `store_type` / `status` / `limit` / `offset` |
| POST | `/api/admin/stores` | 新增 |
| POST | `/api/admin/stores/geocode` | 地址 → GCJ-02 坐标（服务端 Key；未配置 **501**、空地址 **422**） |
| GET / POST | `/api/admin/stores/stock/list`、`/stock/import` | 库存查询 / 批量导入（B5，本轮前端未接） |
| GET | `/api/admin/stores/{id}` | 详情 |
| PUT | `/api/admin/stores/{id}` | **部分更新**（`StoreUpdate` + `exclude_unset`） |
| DELETE | `/api/admin/stores/{id}` | 删除（204；`store_stocks` 外键 CASCADE 连带清除） |

> **v2.6 修复（重要）**：此前 `PUT` 用 `StoreCreate` 全量覆盖，编辑时未提交的 `phone` / `business_hours` / `images` 会被置 `None`、`status` 被默认值 `ONLINE` 顶掉——**编辑一家下线门店会把它悄悄改回在线**。现改为 `StoreUpdate`，并对必填字段显式置空返回 422。
> **路由顺序**：`/geocode` 与 `/stock/*` 必须定义在 `/{store_id}` 之前，否则被 `store_id: int` 抢先匹配返回 422（原 `/stock/*` 就存在此问题，v2.6 一并修正）。
> 门店图片走 `POST /api/admin/upload`（v1.9 起对任意已登录后台账号开放）。

## 2. 城市分组（门店管理下的"按城市聚合"视图）

### 2.1 功能范围
- 按城市聚合门店列表，每个城市为分组标题，其下展示该城市门店。
- 仅前端聚合展示，不引入独立数据模型；城市来源以门店 `city` 字段为准。

### 2.2 关键实现技术
- **数据来源**：前端 `groupBy(city)`（`visibleStores()`）；城市列表另由 `GET /api/stores/cities` 提供，返回 **`[{city, store_count}]`**——不是早期文档写的 `{city, stores[]}`，v2.6 已订正。
- **渲染**：折叠面板（默认展开第一个）+ 每城市门店迷你信息（名称、地址、**坐标**、状态）；点击行按 `data-pid` 直接打开编辑弹窗（不再按名称匹配）。

## 3. 款式列表（v2.3：款式为商品主体，款号自动生成）

### 3.1 功能范围
- 列表列与后端 `items` 表 1:1：**款号 `item_code`**、**主图**（「查看图片」链接，点击 `openImgViewer` 弹大图，无图显示"未设置"）、**款式名称**、**品类 `category`**（款式自带，必填）、**系列**（该款式下挂的系列名，只读；无则"—"）、**热门**（可点击切换 `is_hot`）、**状态**（在售/草稿/已下架）。

> **v2.3 变更（相对 v2.2）**：① **款号不再手填**——新增弹窗的款号输入框恒为只读，按品类实时预览下一个可用款号；② **修复编辑保存失败**（弹窗漏传 `id` → `PUT /undefined`）；③ 列表「查看图片」在 **8000 端口的后台页**也能真正看到图（后端挂载 `/pic`），弹窗图片预览不再空白。

### 3.2 关键实现技术
- `renderStyleRows(list, online)` 统一渲染：在线数据来自 `GET /api/admin/items`，离线数据来自内置 `DEMO_ITEMS`，两者共用同一套渲染逻辑。
- 每行 `data-pid` 关联后端 `id` 并缓存进 `styleRowCache`，编辑/删除/上下架直接取对象，不从 DOM 反解。
- **款号自动生成（v2.3）**：
  - 字段声明 `{ key:'item_code', auto:true, optional:true }`，`openTableModal` 遇到 `auto` 即渲染**只读输入框**，并按 `category` 下拉实时计算预览值 `nextItemCode(cat)`；
  - 前缀与后端一致（`women → SW`、`men → MN`、`kids → KD`），序号取该品类已有款号最大序号 +1，三位补零；
  - 保存时把预览值作为 `item_code` 提交；后端 `create_item` 在**留空**时用 `_next_item_code()` 自行生成，并校验唯一；若前端预览恰好撞号（并发新增）返回 409，前端自动改为留空重试一次，由后端落号。
- **编辑保存（v2.3 修复）**：编辑行的对象必须带 `id`（`openTableModal('styles', { id: it.id, … })`），保存入口再以行 `data-pid` 兜底（`rid`），杜绝 `PUT /api/admin/items/undefined`；早于此版本该路径必然 422 → 后台提示「保存失败」。
- **品类直取款式自身**：后端 `ItemOut.category` 即 `items.category`，前台/后台均按款式的品类展示与筛选。
- **系列随款式返回**：`GET /api/admin/items` 每个款式出参带 `series[]`（该款式下的全部系列），列表「系列」列与「+ 系列」计数直接读它，无需二次请求。
- **图片链路（v2.3 修复）**：数据库只存相对路径（`/pic/hot-01.jpg`、`/uploads/xxx.png`）。
  - 后端挂载 `GET /pic/*` → `frontend/web/public/pic`（只读复用前台同一份图，不复制文件），与已有的 `GET /uploads/*` 一起保证后台页（`:8000/admin`）能取到与前台的**同一张图**；
  - 弹窗图片预览不再限制 `http(s):`/`data:`——**任何非空值都作为图片地址**；且商品图的 `background-image` 写在双引号 HTML 属性里，`url()` 内层改用**单引号**，否则属性会被提前截断（预览长期空白）。
- 上下架：`PUT /api/admin/items/{id}` 只提交 `{status}`；下线后前台对应 URL 404（FR-B26）。
- 热门：`PUT /api/admin/items/{id}` 只提交 `{is_hot}`；前台热门页按 `hot_sort` 排序读取。

### 3.3 接口
`GET /api/admin/items?keyword=&category=&status=&is_hot=`（列表，`category` 直查款式自带品类，`keyword` 同时匹配款名与款号）· `GET/POST/PUT/DELETE /api/admin/items/{id}`

### 3.4 端到端打通（v2.2 / v2.3）
- 后台任何款式/系列改动写入 `fly.db` 后**无需重启**，前台产品页刷新即可见（与 §5.4 新闻链路同一模式）。
- 前台取数层 `frontend/web/src/data/productsApi.js`（对齐 `newsApi.js` 的「空 vs 失败」约定）：
  - `fetchCategoryPage(cat)` → `GET /api/products/{category}`（返回 `{category, items, hot_items}`，每个款式自带 `series[]`）
  - `fetchHotItems()` → `GET /api/products/hot`
  - `fetchAllItems()` → 并发三个品类，供产品中心总览
  - `fetchItemDetail(cat, code)` → `GET /api/products/{category}/{item_code}`（返回款式 + 其 `series[]`，并带同品类款式供「相关推荐」）
- **详情页「旗下系列」= 系列名称链接（v2.3）**：款式详情页（`ItemDetail.jsx`）不再直接铺系列图卡，而是把该款式的系列渲染成一排**以系列名称为文案的链接**；点击弹出系列图片层（`.series-viewer`，展示该系列 `cover_image` + 系列名 + 季节），`Esc`／点遮罩／点关闭均可退出。**系列即层级最底层**，不再往下跳；**该款式没有系列时整个区块不渲染**。

## 4. 系列管理（v2.2：系列挂在款式下，选填 0..n）

### 4.1 功能范围
- **系列 CRUD**：新增/编辑/删除。表格列 = 系列ID、系列名称、**所属款式**（款式名 · 参考款号）、年份、季节、封面图（「查看图片」）、状态；筛选 = 系列名称、所属款式、状态。

- **「所属款式」是下拉选择**，选项实时取自款式列表（在线取 `GET /api/admin/items`，离线取内置 `DEMO_ITEMS`），**不允许手填**——保证系列永远挂在一个真实存在的款式下。
- 款式侧新增/改名后，系列的「所属款式」下拉同步刷新。

> **v2.3 变更**：系列**编辑保存**同样修掉了漏传 `id` 的问题（原先会 `PUT /api/admin/collections/undefined`）；系列封面在后台的「查看图片」与弹窗预览也随 `/pic` 挂载一并生效。

### 4.2 关键实现技术
- 层级：**品类（固定枚举 `men`/`women`/`kids`，后台不提供增删，FR-B28）→ 款式（主体，自带品类）→ 系列（选填）**。系列的品类由所属款式继承，**不再单独存储**。
- 系列下拉链路：`tableConfig.series.fields[].optionsFrom = 'items'` → `selectOptionsFrom('items')` → `currentItems()`。
  - `currentItems()`：**已连接时以服务端为准（即便为空也不退回演示数据）**，避免提交出假的 `item_id`；未连接时用 `DEMO_ITEMS`。
  - 下拉文案形如「廓形短风衣（女装 · CO-SW001）」，避免同名款式混淆。
  - 从款式行点「+ 系列」新建时，弹窗 `item_id` 预选该款式（`openTableModal` 支持 `defaults` 预填）。
- **删除保护（v2.2 反转）**：改为**款式删除**保护——款式下还有系列时，前端先看 `seriesOfItem(it).length`，>0 时提示「该款式下还有 N 个系列…」且不发请求；后端 `DELETE /api/admin/items/{id}` 同样统计并返回 **409** 兜底（避免外键 `ondelete=CASCADE` 静默连删系列）。**系列自身可直接删除**（无子级）。
- 系列的「所属款式」展示由后端 `CollectionOut.item_code` / `item_name` 带出。
- **编辑保存必须带主键**：`openTableModal('series', { id: c.id, … }, tr)`，保存入口再用行 `data-pid` 兜底 —— 与 §3.2 同一处根因。
- 图片：系列封面走 `cover_image`；款式主图走 `images` 数组（取第 1 张作主图，为多图预留）。相对路径（`/pic`、`/uploads`）在后台与前台都能正常显示（见 §3.2「图片链路」）。
- 上传权限：`POST /api/admin/upload` 为**任意已登录后台账号**可用（R2/R3 均可）——修掉 R3 维护款式主图时的 403。

### 4.3 接口
- 系列：`GET/POST/PUT/DELETE /api/admin/collections`、`/collections/{id}`（列表按 `item_id` 过滤，出参含 `item_code`/`item_name`；**新建时校验 `item_id` 存在，否则 400**）
- 款式：`GET/POST/PUT/DELETE /api/admin/items`、`/items/{id}`（下有系列时删除返回 409；新建可留空款号自动生成）
- 上传 / 静态图：`POST /api/admin/upload`（返回 `{"url":"/uploads/xxx.jpg"}`）· `GET /uploads/*` · `GET /pic/*`（前台演示图库，后台共用）
- 前台：`GET /api/products/{category}`、`GET /api/products/hot`、`GET /api/products/{category}/{item_code}`

## 5. 新闻与资讯管理（v1.8：原「新闻管理 + 资讯管理」合并为单页单编辑器）

### 5.1 功能范围
- 企业新闻 CRUD + **富文本编辑发布**（核心需求）。
- 分类：**企业新闻 `company` / 行业资讯 `industry` 两项**（v1.5 起与后端 `NewsCategory` 枚举严格一致；原型的「品牌动态 / 门店开业 / 社会责任」合并为企业新闻，「行业资讯」保留）。
- 状态：已发布 `online` / 草稿 `draft` / 已下线 `offline`（仅 `online` 对前台可见）。
- 作者、发布时间；发布与存草稿两种保存动作。角色：`CONTENT_OPS` + `SUPER_ADMIN` 可见可操作。

### 5.2 关键实现技术
- **富文本编辑器**（落地替换原型的 `document.execCommand`）：
  - 选型：**wangeditor**（中文生态，已定）。提供工具栏：粗体/斜体/下划线/列表/清除格式（原型已含对应按钮）。
  - 正文以 **HTML 存储**；**安全**：出库渲染前做 XSS 清洗（白名单标签属性，如只允许 p/h/h2/ul/ol/li/b/i/u/strong/a/img）。**净化以服务端为主**（后端出库时用 DOMPurify / sanitize-html 处理，白名单同上），前端 `dangerouslySetInnerHTML` 前再做一次净化为辅。
- 发布/存草稿：区别在 `status` 字段（published/draft）。发布校验：标题、正文必填；标题长度限制（如 ≤ 120 字）。
- 列表：状态标签 + 分类筛选 + 分页；「新增/发布」按钮滚动聚焦编辑区。
- 作者：默认取当前登录用户名（从 RBAC session 读）；发布时间 = 发布动作时刻，草稿不显示。
- 封面上传（可选）：用 `POST /api/admin/upload`，存在 news 封面字段。

### 5.3 接口
`GET/POST/PUT/DELETE /api/admin/news`、`/news/{id}`
> 发布/下线语义（status 字段 vs 专用动作端点）以 `app/routers/admin/news.py` 实际实现为准，前端按后端返回的状态渲染，不自行假设。

### 5.4 端到端打通（v1.5 已实现：后台 → articles 表 → 官网新闻页）

**链路**：后台「内容运营 → 新闻与资讯管理」→ `POST|PUT|DELETE /api/admin/news` → `fly.db` 的 `articles` 表 → 前台 `GET /api/news`（列表）与 `GET /api/news/{category}/{slug}`（详情）自动可见，无需重启任何服务。

**后台原型实现要点**（`index.html`）：
- 视图顶端有全局唯一的**连接条**（`#globalApiBar`，v1.7 起）：未连接时为本地演示数据；点「连接后端」用 JWT 登录（token 存 `localStorage.fly_admin_token`），连接后按 `data-view` 分发拉取（banners / content / messages）。
- **单页单编辑器（v1.8）**：原「新闻管理 `view-content` + 资讯管理 `view-tips`」合并为一个视图，`NEWS_SCOPE` 只保留 `content`；列表含「分类」列，一份编辑器通过分类下拉同时发布企业新闻 / 行业资讯。原 `tipTbody` / `tipEditor` / `NEWS_SCOPE.tips` 已移除。
- **筛选（v1.8 强化）**：「查询 / 分类 / 状态」双模式可用——已连接后端时按 `category` / `status` / `keyword` 传参请求 `/api/admin/news`；离线演示时对当前表格行做本地过滤；「重置」清空条件并恢复全部。
- 表格行渲染带 `data-nid`（后端主键）；「编辑」先 `GET /api/admin/news/{id}` 取全文回填编辑器，「删除」调 `DELETE` 后自动重新拉取。
- 「发布」= `status: online`；「存草稿」= `status: draft`。新建时自动补 `slug = news-<时间戳36进制>`；**发布时若未填 `published_at`，后端自动填当前时间**（避免前台按发布时间排序时掉到末尾）。
- 编辑器字段：标题、分类（`company`/`industry`）、**作者（`author`，v2.5 新增下拉：超管 / 内容运营 / 门店商品运营；列表「作者」列此前无法录入，现补齐）**、摘要（→ `summary`，前台列表的 lead）、封面（→ `cover_image`，走 `POST /api/admin/upload`）、正文（contenteditable 的 HTML → `content`）。
- **安全**：正文入库前经后端 `sanitize_html()`（bleach 白名单 + 整体摘除 `script/style/iframe` 及其内容），前台以 `dangerouslySetInnerHTML` 渲染的已是净化后内容。

**前台实现要点**（`frontend/web`，v1.6 更新）：
- `src/data/newsApi.js` 为统一接入层，**明确区分「空」与「失败」**：
  - `fetchNewsList(cat)` / `fetchLatestNews(n)` 返回 `{ ok, items }`：`ok=true` 时 `items` **可以是空数组**（后台真的没内容）；`ok=false` 才表示接口不可用。
  - `fetchNewsDetail(cat, slug)` 返回 `{ ok, article }`：`ok=true, article=null` 表示后端确认该文不存在或未发布；`ok=false` 表示接口不可用。
- `NewsList.jsx`：接口成功 → 按返回内容渲染（为空则显示「暂无…内容」空状态）；接口失败 → 才回退本地 `siteData.NEWS`，并在页头提示「后端暂不可用」。加载中不渲染兜底内容（避免本地默认闪现）。
- `NewsDetail.jsx`：同上策略；仅当接口确认不存在才跳回列表（加载中不跳转）。
- `Home.jsx` 首页「品牌动态」区块（v1.6 起）：改为调用 `fetchLatestNews(3)` 读接口，**与 `/news` 完全同源**，不再使用写死的 `NEWS`。
- 详情页正文：有 `html` 走 `dangerouslySetInnerHTML`，否则回退本地结构化 `body` 节点渲染。

**已知取舍**：后端暂无分页需求（后台列表一次拉全量，前台 `page_size=50`）。

### 5.5 数据一致性（v1.6：单一权威源 + 种子数据）

**问题背景**：此前存在两套数据源——前端写死的 `siteData.NEWS`（9 条）与数据库 `articles`，且未约定谁是权威，导致三类错位：① 后台删除后列表不刷新（需刷新浏览器）；② 后台清空后前台仍显示默认内容；③ 首页显示默认、`/news` 显示数据库内容，两者不一致。

**修复与约定**：
1. **删除即时刷新（bug 修复）**：FastAPI 的 `DELETE` 返回 `204 No Content`，但响应头仍带 `content-type: application/json`（实测）。后台原型 `apiCall()` 原先只要 content-type 含 json 就调用 `r.json()`，对空响应体解析抛错，导致「删完重新拉列表」的后续逻辑被跳过（数据库其实已删，仅界面未刷新）。现 `apiCall()` 对 `204/205` 直接返回 `null`，并给 `r.json()` 加降级 `catch`，删除后列表立即刷新（留言删除同理）。
2. **前台以数据库为准**：接口成功但为空 → 前台显示空状态；仅当接口失败才回退本地默认（见 §5.4）。首页与 `/news` 统一读接口，同源。
3. **种子数据**：新增 `backend/种子数据.py`，把前端默认新闻灌入 `articles` 表，使「数据库 / 后台 / 首页 / 新闻列表」起点一致。用法见 `backend/README.md`。
   - 从 `frontend/web/src/data/siteData.js` 的 `NEWS` **动态提取**（Node `import`），避免手写重复数据导致漂移。

## 8. 留言管理（v1.5 完成端到端联动）

> 模块入口：侧栏「运营 → **留言管理**」；角色：`SUPER_ADMIN`、`CONTENT_OPS`。
> 数据来源：前台「联系我们」表单提交 → `contact_messages` 表；后台负责查看、处理、软删除。

### 8.1 功能范围
- 列表：卡片式展示姓名、公司、处理状态、提交时间、编号（`M{id}`）、合作类型、留言内容、联系方式（**默认脱敏，超管可见明文**）、处理记录。

- 删除：**软删除**（`is_deleted=1`），列表不再展示，数据保留用于审计与个人信息删除权追溯。
- 筛选：关键词（姓名 / 公司 / 留言内容）+ 状态（待处理 / 已联系 / 已关闭），均下推到接口。

### 8.2 关键实现技术
- **脱敏规则**：`_mask()` 对邮箱保留前 2 位与域名、对手机号保留前 3 后 2；`show_full_contact` 仅 `SUPER_ADMIN` 为 true，并额外返回明文 `contact_full`。
- **软删除字段**：`contact_messages.is_deleted`（`BOOLEAN DEFAULT 0`），由 `backend/轻量迁移.py` 幂等补齐（项目未引入 Alembic；以后新增列只需在该脚本 `MIGRATIONS` 里登记一行）。
- **健壮性**：枚举取值统一经 `_val()` 兼容枚举与字符串，避免脏数据让整个列表 500。
- **操作日志**：处理与删除均写 `log_operation`（对象类型 `contact`）。

|---|---|---|

## 9. 数据流与鉴权（横切关注点）

- **鉴权**：前端路由守卫按角色显隐菜单/入口（已原型化 `data-roles`）；后端每个接口 `require_roles` 兜底（越权 403，对齐 FR-B57）。
- **登录**：`POST /api/admin/auth/login`（对齐技术方案 §1/§6）返回 token + 角色；**Token 存储优先采用 httpOnly + SameSite Cookie**（由后端 Set-Cookie 下发，前端不接触原始 token）；若一期受限需暂用 localStorage，须标注 XSS 风险并限期迁移 → 路由守卫 + Query 统一注入 Authorization。
- **数据失效（v1.6 已落地）**：后台原型在增删改成功后**立即重新拉取**对应列表（`loadNews` / `loadContacts` / `loadBanners`），无需刷新页面；前台每次进入页面即请求接口读库，因此「后台改完 → 前台可见」无需额外推送。注意 `apiCall()` 对 `204` 空响应体的处理见 §5.5。

### 9.1 全局后端连接条（v1.7）

**问题**：v1.5 时为「新闻 / 资讯 / 轮播 / 留言」四个视图各插入了一个 `.api-bar`（连接后端 / 重新拉取 / 断开）。四处各写一套 DOM 与绑定，其中「网页管理 · 首页轮播图」那处仍是**旧 id 写法**（`#apiState` / `#btnApiConnect`），而统一的 `refreshApiBar()` 已改为按 class 选择器（`.api-state` / `.btn-api-connect`）查找，于是轮播图那条被 `if (!st) return` 直接跳过——表现为「其它页面按钮正常，轮播图这里按钮失效」。

**改法（共用同一条）**：删掉四个视图内的连接条，在 `<main class="content">` 顶部放**唯一一个** `#globalApiBar`（`position:sticky; top:0`，所有视图都能看到），并把逻辑统一：

```js
var currentView = 'dashboard';                 // switchView() 里同步更新
var API_LOADERS = {                            // 视图 → 数据加载器
  banners:  function (s) { return loadBanners(s); },
  content:  function (s) { return loadNews('content', s); },
  tips:     function (s) { return loadNews('tips', s); },
  messages: function (s) { return loadMessages(s); }
};
```

- `refreshApiBar()` / `initApiBars()` 只针对 `#globalApiBar` 一个节点，不再遍历 `.api-bar`。
- `switchView()` 里记录 `currentView`；**已连接时**切到 `content / tips / banners / messages` 会按 `API_LOADERS[v]` 自动拉取最新数据。
- 「重新拉取」按钮 = 拉取**当前视图**对应的接口（按 `currentView` 查表）。
- **新增模块只需在 `API_LOADERS` 登记一行**，连接条自动支持，不会再出现「某个页面漏了、按钮失效」。

> 回归：`global_apibar_test.js`（页面仅 1 个连接条 / 连接 → 断开 / 切到四个视图连接条始终可用且触发对应接口）与 `news_msg_test.js` 均已覆盖。

测试过程会反复增删数据，需要随时能回到「干净初始态」。为此提供：

| 组成 | 位置 | 说明 |
|------|------|------|
| 初始基准 | `backend/初始数据/初始数据库.db` | 干净初始快照（SQLite 文件）。**这是权威基准，请勿删除** |
| 重置脚本 | `backend/重置数据库.py` | `python 重置数据库.py` 用基准覆盖 `fly.db`；`--show` 看状态；`--seed` 只重灌 9 条新闻；`--snapshot` 把当前库另存为新基准 |
| 商品种子 | `backend/种子数据_商品.py` | **v2.4 新增入口**：只清空并重灌 `items` / `collections`（5 款式 / 8 系列），不动新闻/轮播/留言 |
| 启动入口 | `启动.bat` / `start.bat` 菜单项 **5 / 6 / 7** | 5 = 整库恢复初始数据（先停 8000 服务再重置）；6 = 查看数据库状态；**7 = 恢复款式/系列种子数据（只重灌商品）**（v2.4） |

- 覆盖走 **SQLite backup API**（一致性快照），不是简单文件拷贝。
- 基准缺失时会**现场兜底重建**（建表 + 3 账号 + 6 固定页 + 首页 7 区块含 4 帧轮播 + 9 条新闻 + **5 款式 / 8 系列**）；注意兜底不含门店数据，因此**基准文件仍需保留**。
- 重置前必须**停止后端服务**（脚本会检测 8000 端口占用并提示），否则数据库文件被占用会失败。

## 10. 安全与合规

- 富文本 XSS 清洗（见 §5.2）；上传接口（`POST /api/admin/upload`）**禁止 SVG/含脚本 HTML**，仅允许图片类型（jpg/png/webp），限制大小（对齐 `UPLOAD_MAX_MB`），生成唯一文件名并做 MIME 校验。
- 门店/新闻经纬度与内容字段：文本 length 限制防注入；统一 DB 参数化查询（后端职责）。
- 涉及内容公开的新闻/门店上下线动作须写入**操作日志**：见《后台管理系统-技术方案》B6（操作日志 / 登录日志，`/admin/logs`），由后端 `app/routers/admin` 记录，前端仅触发动作、不实现日志 UI。
