# FLY 品牌官网 · 后台管理系统技术方案

> 版本：v1.0 ｜ 日期：2026-09-08 ｜ 状态：方案待评审
> 依据：`docs/FLY品牌官网_PRD_v1.0.md`（v1.4 评审修订版）+ 后端现有 `app/routers/admin` 接口清单

---

## 0. 一页结论

FLY 官网后台 = **一套面向"不懂代码的运营人员"的可视化内容管理平台（RuoYi 风格）**。

- **定位**：让运营在网页上就能维护官网内容——首页轮播图/图片、企业新闻、产品/系列、门店、联系留言、账号权限，改完点"发布"，官网前台立即/短时生效。**不需要懂代码，也不需要碰数据库。**
- **形态**：一个**独立的 React SPA**（后台），与官网前台（当前为纯 SPA，SSR 二期规划中，`frontend/web`）完全分开。PRD 第 4.1 节明确：后台 React SPA + Ant Design。
- **后端**：直接复用现有 FastAPI 后台接口（`app/routers/admin/` 已就绪），仅需**补 1 个文件上传接口**。
- **用户**：PRD 已定义**三角色 RBAC**，无需重新设计（见 §4）。

现状与目标对照：

| 角色 | 现状 | 目标 |
|---|---|---|
| 运营人员 | 只能手动改代码、改数据库 | 可视化后台自助维护内容 |
| 开发人员 | 每次改内容都要发版 | 内容变更与代码发布解耦 |
| 官网前台 | 硬编码/空壳 | 内容由后台配置驱动，实时反映 |

## 1. 技术栈

| 层 | 选型 | 说明 / 依据 |
|---|---|---|
| 后台前端框架 | **React 18 + Vite + React Router** | PRD 4.1「后台 React SPA + Ant Design」 |
| UI 组件库 | **Ant Design (antd v5)** | RuoYi 风格、面向运营的中后台表单/表格/弹窗，生态成熟 |
| 状态管理 | **TanStack Query（数据）+ Zustand（UI 态）** | 列表/表单数据缓存、乐观更新 |
| 富文本 | **wangeditor**（已定） | 新闻正文、固定页内容；出库需 XSS 过滤——**以服务端净化为主**（DOMPurify / sanitize-html，白名单对齐 NFR-18），前端净化为辅 |
| 图表（看板） | **@ant-design/charts** | 后台首页 dashboard 数据可视化 |
| 地图选点 | **腾讯地图 JS API（选点）** | 门店经纬度可在后台地图上点选（与官网前台统一为腾讯地图；PRD 默认假设为高德，已据已申请 API 调整为腾讯，偏差可控） |
| 后端 | **现有 FastAPI（Python 3.13 venv）** | 复用 `app/routers/admin/`，零框架改动 |
| 鉴权 | **JWT + 轻量 RBAC**（后端已实现） | `app/dependencies.py`：`/api/admin/auth/login` 换取 token，`CurrentSuperAdmin` / `CurrentContentOps` / `CurrentMerchStoreOps`；**Token 优先采用 httpOnly + SameSite Cookie 下发，前端仅存于内存/状态，避免 localStorage（XSS 风险）** |
| 文件存储 | **本地磁盘 `uploads/`（一期）** | 后台传图存静态目录，Nginx 直出；二期可切 OSS/COS |
| 数据库 | **SQLite（async，aiosqlite，单文件零运维）** | PRD v1.5 定稿统一使用 SQLite（本地/生产一致），代码层无需改动 |

> 后台前端独立目录，建议放：`frontend/admin`（与 `frontend/web` 官网前台并列）。开发端口 `5174`（避让官网 3000/5173），生产构建后由 Nginx 托管于 `/admin` 路径。

## 2. 总体架构

```
┌──────────────┐   ┌──────────────┐
│ 官网前台      │   │  后台管理系统  │  ← 两个独立前端应用
│ React SPA    │   │  React SPA   │
│ :3000        │   │  + AntD      │
│ (frontend/   │   │  /admin      │
│  web)        │   │  :5174       │
└──────┬───────┘   └──────┬───────┘
       │ 公开只读         │  JWT 登录 + RBAC
       ▼                 ▼
┌──────────────────────────────────┐
│      FastAPI (backend，:8000)      │
│  /api/public/*     /api/admin/*    │
│  （已就绪：auth / dashboard /     │
│    news / collections / items /    │
│    stores / stores-cities(公开) /  │
│    contacts / pages / admin_users）│
│  + 【待补】文件上传接口 /api/admin/upload│
└──────────────────┬───────────────┘
                   ▼
        ┌───────────────────────┐
        │   SQLite（单文件）    │ ← 统一数据库（v1.5 定稿）
        └───────────────────────┘
```

关键点：
- **前后台彻底分离**：官网前台当前为纯 SPA（SSR 保 SEO 列入二期）；后台做 SPA 保开发效率。两者只通过后端 API 通信，互不依赖。
- **认证隔离**：后台走 `/api/admin/auth/login`（JWT），官网前台匿名无登录态（PRD Non-goal，删除了会员）。
- **权限在前后端双重校验**：菜单/按钮按角色显隐（前端）+ 每个接口 `require_roles`（后端，越权返回 403，对齐 FR-B57）。
- **公开只读接口**：`/api/stores/cities` 供前台门店地图与后台城市分组共用，无 RBAC 保护（见 §6）。

## 4. 角色与权限（PRD 已定，直接采用）

**轻量 RBAC 三角色**（PRD 3.2 行158-166、"谁生产内容谁维护"）：

| 角色 | 代号 | 能做什么 | 不能做什么 |
|---|---|---|---|
| **超级管理员** | `SUPER_ADMIN` | 账号管理、全部模块、删除内容、角色分配 | —（全权） |
| **内容运营** | `CONTENT_OPS` | 首页装修、企业新闻、固定页、联系留言、**全站图片素材** | 不可改商品/门店结构化主数据 |
| **商品门店运营** | `MERCH_STORE_OPS` | 产品/系列、款式、门店主数据、库存 | 不可改首页、不可发新闻 |

实现：后端依赖注入已提供 `CurrentSuperAdmin / CurrentContentOps / CurrentMerchStoreOps`（`app/dependencies.py`）。前端在登录后按 `user.role` 渲染对应菜单，并对请求做二次拦截。

## 5. 页面清单（后台 SPA 路由）

```
/admin            → 登录页
/admin/dashboard  → 工作台（概览：待审核/草稿数、访问概览、快捷入口）
/admin/home       → 首页装修（区块列表 + 轮播帧编辑）
/admin/news       → 企业新闻（列表 + 新增/编辑 + 发布/下线）
/admin/pages      → 固定页管理（关于我们/品牌介绍/发展历程/联系我们/招聘页）
/admin/messages   → 联系留言（列表 + 标记处理状态）
/admin/products   → 产品系列（列表 + 编辑）
/admin/items      → 款式管理（系列下款式 + 热门标记）
/admin/stores     → 门店管理（列表 + 地图选点表单）
/admin/inventory  → 门店有货查询（运营内部）
/admin/accounts   → 账号管理（超级管理员）
/admin/roles      → 角色（如与账号合并可在此展示权限矩阵）
/admin/logs       → 操作日志 / 登录日志
```

布局采用经典后台框架：**左侧可折叠菜单 + 顶部栏（面包屑/全屏/用户下拉）+ 内容区**。

## 6. 接口映射（对齐后端现有路由）

| 后台页面 | 调用的后端接口（前缀 `/api/admin`） |
|---|---|
| 登录 | `POST /auth/login` → `{access_token}` |
| 工作台 | `GET /dashboard/{...}`（看板聚合） |
| 首页装修 | `GET/POST/PUT /pages`、`/pages/{id}`（Page/Version/Block） |
| 企业新闻 | `GET/POST/PUT/DELETE /news`、`/news/{id}` |
| 固定页 | 同上 `/pages`（`page_type=fixed`） |
| 系列 | `GET/POST/PUT/DELETE /collections`、`/collections/{id}` |
| 款式 | `GET/POST/PUT/DELETE /items`、`/items/{id}` |
| 门店 | `GET/POST/PUT/DELETE /stores`、`/stores/{id}`、`GET /stores/cities`（**城市分组，公开只读，无 RBAC**，返回 `{city, stores[]}`） |
| 留言 | `GET /contacts`、`PUT /contacts/{id}`（处理状态） |
| 账号 | `GET/POST/PUT/DELETE /admin-users`、`/admin-users/{id}` |
| 图片上传 | **`POST /api/admin/upload`（待补，见 §8 缺口）** |

> 具体字段以 `app/schemas/*.py` 为准；后端接口已带 RBAC 约束，前端直接调用即可。`/api/stores/cities` 为公开只读接口（供前台门店地图与后台城市分组共用），不计入 RBAC 保护范围。

## 8. 后端缺口与待确认项

**后端缺口（必须补，才能"传图"）：**
1. **文件上传接口** `POST /api/admin/upload` —— 目前 `app/config.py` 有 `UPLOAD_MAX_MB=10`，但路由列表里**没有上传接口**。后台要"首页图片添加/新闻封面/款式图"就必须有这个。需：限制类型/大小、生成唯一文件名、存 `uploads/` 静态目录、返回可访问 URL、并入操作日志。
2. **静态文件服务** —— 需用 `StaticFiles` 挂载 `/uploads`，或用 Nginx 直接托管。
3. **管理员种子账号** —— 确认 `app.seed` 是否已生成一个 `SUPER_ADMIN` 账号（供登录后台）。

**待确认项（请你拍板）：**
- Q1. 后台开发端口用 **5174** 可以吗？（官网前台占 3000）
- Q2. 富文本编辑器：**已定 wangeditor**（轻量、中文友好，供运营编辑新闻/固定页正文）。（原候选 tiptap 不再采用）
- Q3. 门店经纬度用**腾讯地图点选**（已确认，与官网前台统一为腾讯；PRD 默认假设为高德，属可控偏差）。✅ 已决策
- Q4. 一期先覆盖哪几个模块最优先？建议顺序：**账号登录 → 企业新闻 → 首页装修 → 商品系列 → 门店 → 留言 → 固定页**。（你提到的"首页图片添加/企业新闻/产品添加"已包含）
- Q5. 图片上传存**本地 `uploads/`**（一期）即可，还是要一次到位接对象存储（OSS/COS）？
- Q6. 是否需要"门店有货查询"（B5）进一期，还是按下文建议二期？

## 9. 建议的分期（防范围蔓延）

- **一期（MVP，先用起来）**：登录/RBAC + 首页装修（轮播/图片）+ 企业新闻 + 产品系列/款式 + 门店（不含批量导入）+ 联系留言 + 账号管理。
- **二期（可选）**：固定页可视化装修增强、操作日志可视化、库存查询、定时发布、版本回滚界面、招聘信息管理、内容审核流。
- **明确不做（对齐 PRD Non-goals）**：在线交易、会员登录、订单售后、多语言（架构预留）、多商户。

## 10. 上手步骤（拿到评审通过后）

1. 确认后端补上传接口 + 静态服务（§8），重启 8000。
2. `cd frontend/admin && npm create vite@latest . -- --template react`，装 antd / axios / TanStack Query / react-router。
3. 搭 Layout 骨架（侧栏/顶栏）+ 登录页 + 路由守卫。
4. 接企业新闻模块（列表/表单/富文本）打通第一条链路。
5. 按下文建议优先级逐个补模块，每模块后端已就绪，专注前端。
